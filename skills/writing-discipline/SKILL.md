# 写作纪律（dsh-writing-discipline）

**一句话**：交付前必须让文本过一遍扫描器；这件事不该靠记性，插件已经把它做成 `present` 前的机械闸门。

## 1. 什么时候用

写或改任何**有读者的文本**：报告、方案、案例分析、课程作业、产品文案、README、邮件、给用户的正式回答。
只要最后会 `present` 一个 `.docx/.pdf/.md/.pptx/.xlsx`，本 skill 就是必走流程。

## 2. 三步流程

```text
写之前  →  wd_rules({"profile":"report"})        看清规则，避免写完再返工
写完    →  wd_scan({"filePath":"X.docx","profile":"report"})    target: ERROR = 0
改稿后  →  wd_conservation({originalPath, revisedPath})      数字/引用/否定/主张强度不许漂移
交付    →  present({files:[{path:"X.docx"}]})                 闸门按内容 sha256 自动校验
```

- `profile` 按文体选：`report`（方案/作业）、`academic`（论文，hedge 自动降级）、`readme`、`email`、`chat`、`comment`。
- `wd_scan` 直接吃 `.docx/.pptx/.xlsx`，内部抽正文再扫；不要先导成 txt 再扫（容易漏表格里的字）。
- 扫描 `filePath` 会记账。**文件一改 hash 就变**，旧通行证立即失效，必须重扫。
- `.pdf` 认源文件：同目录同名 `.docx/.pptx/.xlsx/.md/.tex` 通过即放行。

## 3. 闸门怎么拦

`present` 前检查每个待交付文件：

| 情况 | 结果 |
|---|---|
| 扫描过且 ERROR 0，内容未变 | 放行 |
| 从未扫描 | 拒绝，给出该文件的确切 `wd_scan` 命令 |
| 扫描后又有 ERROR | 拒绝，要求改完重扫 |
| 扫描后又改过文件 | 拒绝，提示重新扫描 |
| 非文档（图片、数据、压缩包） | 不拦 |

被拦时照 reason 做，不要换文件、拆成多次 `present`、或用 `wd_gate reset` 绕过——闸门按内容指纹判定，换文件等于从零记账。

## 4. 高频返工点（先自查能省两轮）

1. **破折号过密**：密度 > 5‰ 就会被标记。中文里 `——` 常被当成万能连接词；改冒号、句号、括号，列表用 `→`。表格里表示"无"的 `—` 也算，改 `／`。
2. **「不是X而是Y」连用**：全文超过 2 次就是套路。留最有力的一处，其余改肯定句。
3. **超长句**：一句超过 ~60 字就该拆。一句话只装一个判断。
4. **封面/文首免责**："仅代表个人""如有错误请指正""本文不构成…"——删，或改成方法说明（数据来源、样本量、统计口径）。
5. **软对冲**："大约""或许""可能比较" → 换成区间、样本量、方向性结论。
6. **过程旁白**："我先查了…然后发现…" → 只留结论与证据。

## 5. 什么时候用 wd_rewrite，什么时候手改

- `wd_rewrite` 只做确定性的机械操作：删防御性引子、压限定词、删纯防御句（含数字/引用/图号的句子不删）。适合清稿第一步。
- 语义层面的改写（换句式、拆长句、重排论证）得手改或让模型改；改完必须 `wd_conservation` 复核。

## 6. 与 anti-defensive-writing 的分工

- `anti-defensive-writing`（skill）：管"为什么不能这么写"、五类病灶、删改顺序、自检清单，给人看。
- `dsh-writing-discipline`（本插件）：管"机器能判的那部分"——扫描、记账、闸门、守恒锁。
- 两者规则不重叠：语气谦卑的防御性文本会被前者抓；语气自信但句式套路（破折号、对比句）的模型味只有后者抓得到。两套都要过。
