# 数据边界：什么开源，什么只在你机器上

一句话：**代码和规则全开源，你的文字永远不出本机。**

## 只在你机器上的（不入仓库、不上传）

| 文件 | 位置 | 里面是什么 |
|---|---|---|
| `baseline.json` | `~/.dsh/writing-discipline/` | 你的文风基线：句长、参差度、常用词、一句原型句 |
| `learned.json` | `~/.dsh/writing-discipline/` | 你标记的误报与自选词 |
| `像不像你-*.html` | 你自己指定的目录 | 生成的报告（含你的原文片段） |

这些路径已经写进 `.gitignore`，`git status` 永远不会看到它们。仓库里也没有任何示例基线——`docs/` 下的数字来自公开语料，不是某个人的稿子。

## 开源的（仓库里全部内容）

- 规则表（24 条通用 + 24 条中文 + 6 条密度/结构）
- 文风指纹算法与阈值
- 守恒锁、改写器、交付闸门
- CLI、浏览器版采集页、标定工具
- 测试与 CI

## 为什么指纹算法也开源

它不依赖任何人的数据才有意义——基线是你自己的，算法是通用的尺子。开源的是尺子，不是你的身高。

## 如果你要的「藏私」是别的

有两种可能，处理方式不同：

1. **不想让某条规则公开**：从 `lib/rules.js` 删掉对应条目即可，但那会让所有人的规则集不一致。更干净的做法是留一条 `learned.json` 覆盖，只影响你自己的机器。
2. **已经把东西推上去了想撤回**：代码一旦进过公开仓库历史，删除文件不等于删除历史。真要抹掉得重写提交历史并强推，代价是别人的 clone 全部失效。这个操作破坏性大，动手前先想清楚。

## 本地数据怎么清

```bash
# 只删基线（下次重新采集）
rm ~/.dsh/writing-discipline/baseline.json
# 只删词表
rm ~/.dsh/writing-discipline/learned.json
# 全删
rm -rf ~/.dsh/writing-discipline
```

插件不会因为文件缺失而报错——没有基线就自动降级，没有词表就只用内置规则。
